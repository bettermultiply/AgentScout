# 树形绘制参考（2026-11-12）

这份文档只记录本轮实际看过、评估过的外部项目和算法，以及我们采用了什么、没采用什么和原因。它不描述 AScout 自己的目标语义；目标语义在 `docs/development/web-ui.md`。

## EZ-Tree（dgreenheck/ez-tree）

- 地址：https://github.com/dgreenheck/ez-tree
- 形态：Three.js 的程序化树生成器，发布为 `@dgreenheck/ez-tree`。本轮读过 `src/lib/tree.js`、`src/lib/rng.js`、`src/lib/options.js` 与 README。
- 它是 3D 的，我们只借鉴算法，不引入 three.js 依赖，也不使用它的网格/LOD 代码。

它做的事情：

- **确定性随机**：`RNG` 用一组乘加状态（`m_w`/`m_z`），同一个 seed 每次生成同一棵树。
- **分级参数**：每一级有独立的 `length`、`radius`、`angle`、`taper`、`gnarliness`、`sections`、`start`、`children`。
- **逐段收缩**：第 i 段的半径乘 `1 - taper[level] * i / sectionCount`；常绿树直接收到 0。
- **gnarliness 按半径放大**：每段把朝向随机偏移 `max(1, 1/sqrt(radius)) * gnarliness[level]`，枝越细摆动越大。
- **生长力**：把每段的生长方向按 `force.direction` 旋转，单步角度受 `force.strength / sectionRadius` 限制。
- **子枝分层布置**：沿父枝用 `startMin + (i + rng.random()) * heightStep` 分层抖动；径向角用固定槽位再加抖动，槽位顺序随机置换，避免高度和方向相关。
- **子枝角度**：每一级一个固定 angle，依靠径向槽位分散，而不是每个子枝换一个角度。
- **叶片**：沿枝分层放置，随机径向角，`sizeVariance` 给每片叶不同大小。

当时借用、后来部分撤掉的东西：

- 兄弟枝分散：曾改成连续角度区间、同侧至少相差 15° 和左右随机游走，2026-11-12 已删除，改为逐截左右行走。
- “一次模型调用是一根叶茎、工具调用是茎上的叶片”的复叶结构，保留。
- 叶片尺寸由数据里的耗时决定，保留。
- 生长方向约束：曾简化成“分叉点离开种子轴后一律向外”，2026-11-12 已删除。

本轮不采用：

- 3D 网格、three.js、LOD、树皮纹理。我们的树是二维的，节点只有几十个。
- 程序化拓扑和固定分级参数。AScout 的树结构来自真实观察事件，不能为了好看发明 Branch 或调用。
- `taper[level]` 和 `radius[level]`。我们不知道“级别半径”，用“这个点之后还有多少调用”代替。
- gnarliness 随半径放大。本轮的主干曲率仍由确定性的指数回正控制，尚未接入按半径放大的抖动。

## 2D 实现调研（2026-11-12，第二轮）

这一轮实际读了三个二维实现。它们都是“生成树”，不是“把已有事件排成一棵树”，所以借鉴的是**枝干粗细、弯曲、连接和生长**的画法，而不是拓扑。

### luciopaiva/tree

- 地址：https://github.com/luciopaiva/tree
- 读过的文件：`tree.js`、`index.js`。二维、Canvas、space colonization。
- 常量：`NEXT_SEGMENT_WIDTH_RATIO = 0.986`、`NEW_BRANCH_WIDTH_RATIO = 0.6`、`MIN_BRANCH_WIDTH_RATIO = 0.1`、`MIN_ANGLE_FOR_BRANCHING_IN_DEGREES = 8`、`MAXIMUM_NUMBER_OF_BRANCHES = 100`。
- 每一段是一小步；新段宽度 = 父段 `currentWidth`，随后 `currentWidth *= 0.986`。子枝起点宽 = 父段 `finalWidth × 0.6`，永远不会接近父枝的宽度。
- 新段从 `finalWidth × 0.01` 开始，之后每帧向 `finalWidth` 加一步 `finalWidth × 0.01`。因此“长出来”的部分先细后粗，不需要重画已有枝干。
- 弯曲不是一个回正函数，而是 `baseAngle + sin(t) × 15° + sin(2t) × 0.8 × 15°`，`t` 按段递增 2.5 圈/秒。两根低频正弦叠加，得到连续、可重复但不规则的摆动。
- 章动之外还有：只允许向上生长（`acc.y < -1` 的吸引方向被丢弃）；主干不参与吸引（`TRUNK_DOES_NOT_GET_ATTRACTED`）；新枝与父枝夹角必须落在 8°–172°，否则不生成，用来避免无限分叉。
- 绘制：每段单独 `lineTo`，`lineWidth` 取该段宽度；先画一遍深色描边，再画一遍木色，`lineJoin/lineCap = round`。没有做轮廓并集。
- 坐标：树被归一化到 2 单位宽、固定高度的框里，最后按屏幕高度缩放。

可借鉴：

- **子枝起点宽封顶在父宽的 0.6 左右**。这能避免“单子枝几乎和父枝一样粗”，让分叉一眼看得出来。
- **段宽从 1% 长到最终宽度**，是“只让新增部分生长”的最小实现；已有段的几何不动。
- **两根低频正弦做摆动**，比现在的指数回正更容易得到自然的枝干起伏，而且不依赖枝长。

### jasonwebb/2d-space-colonization-experiments

- 地址：https://github.com/jasonwebb/2d-space-colonization-experiments
- 读过的文件：`core/Network.js`、`core/Node.js`、`core/Path.js`；文章：https://medium.com/@jason.webb/space-colonization-algorithm-in-javascript-6f683b743dc5
- 二维、Canvas，另有 SVG 导出；所有点用 `kdbush` 做空间索引。
- **增粗（canalization）**：每次长出一个新梢，就沿父链向上走；如果 `parent.thickness < child.thickness + 0.07`，把父节点设为 `child.thickness + 0.03`。也就是“父节点至少比最粗的子节点粗一点”，厚度由后代累积，不会回退。
- 绘制时线宽 = 基础宽度 + `thickness`；`EnableOpacityBlending` 开启时透明度 = `thickness / 3 + 0.2`，越细的梢越淡。
- **边界和障碍**：`Path.contains(x, y)` 用点在多边形内判断；新节点必须落在 Bounds 内、不能进入 Obstacle。注释说明障碍就是用来挡住生长的。
- 开放/闭合脉序两种吸引规则、相对邻域过滤；平均方向加一个小抖动，避免卡在两个吸引点之间。

可借鉴：

- **“父节点比最粗子节点粗”** 的增粗原则，和我们的“之后还有多少调用”是同一个语义；它的实现是增量的，新增事件只改祖先链，不用重算全树。
- **把已有主干当作子枝的障碍**。这比现在“离开种子轴就向外长”的启发式更硬：孙枝如果会穿进主干的轮廓，就不生成那一段。
- **细梢更透明**，可以用很低的成本给树冠做出纵深。

不适用：

- 吸引点决定拓扑。AScout 的拓扑来自真实 Branch 和调用，不能让吸引点发明枝。
- 为几千个节点准备的空间索引；我们现在是几十个节点。

### walsh9/topiary

- 地址：https://github.com/walsh9/topiary
- 读过的文件：`src/topiary.js`。二维、Canvas、递归分形树。
- 每一级：`height *= random(0.6, 0.9)`，`thickness *= random(0.6, 0.9)`；左右两侧有各自的角度区间（默认都是 10–40°），生成时左侧减、右侧加，天然不对称。
- 每一根枝就是一条直线，`lineWidth = thickness`；子枝从父枝端点开始，接缝处不做任何处理。
- `delay` 用 `setTimeout` 把递归展开成按时间逐枝绘制，形成“树在长”的动画；没有种子，`Math.random` 每次不同。
- 可选彩虹模式：每条枝的起终点做色相渐变。

可借鉴：

- **左右两侧使用不同的角度区间**，比对称的 ± 角度更像真树；我们现在两侧共用 26–56°。
- **按绘制顺序延迟** 是最简单的生长动画；但它会把枝画成直线，且不可复现，只能作为“动画顺序”的参考。

不适用：

- 固定递归深度、每级固定两个子枝。我们的枝数、层级和存在时间都来自事件。
- 无种子随机；我们的图必须可重复。

### 这些参考后来没有进入实现

2026-11-12 的树形修正把下面几项全部撤掉，理由和替代规则见 `decisions.md` 同日条目：

- 子枝起点宽不再按父宽 0.9 封顶，改由剩余调用份额的平方根从父枝宽度推导。
- 不再把祖先主干当障碍，也不做换边；子枝沿父枝局部方向垂直长出。
- 不再使用距离制指数回正或双正弦弯曲；方向改为逐截左右行走。
- 保留的只有“一次模型调用一根叶茎，工具调用是茎上的叶片”的复叶结构，以及叶片尺寸由耗时决定。

## 其他评估过、本轮未采用的算法

- **Space colonization**（Runions、Lane、Prusinkiewicz，2007）：用吸引点生长出自然的分枝。需要先发明吸引点和生长规则，等于用算法重造拓扑，和“只画观察到的 Branch”冲突，不采用。
- **L-system**：由文法生成拓扑。同样会发明事件里没有的分枝，不采用。
- **简单递归分叉（每级固定子枝数）**：会让同一父枝的候选看起来像一个模子，也无法表达“这一枝只跑了 2 次调用”。

## 评估过、本轮未引入的库

| 库 | 能做什么 | 优点 | 缺点 / 为什么本轮不用 |
|---|---|---|---|
| `d3-shape` | 从点集生成平滑曲线和面积路径 | 成熟、体积小、按需引入 | 我们的中心线需要在每个节点指定切线并做弧长反馈，`curveCatmullRom` 表达不了；现有 Hermite 采样更直接 |
| `d3-hierarchy` | tidy tree / cluster 布局 | 标准树布局 | 我们的纵坐标是逻辑时间，不是层级深度；用了反而要丢掉时间 |
| `paper.js` | 完整二维矢量，`Path.unite` 做布尔并集 | 能真正把父枝和子枝合成一个轮廓 | 体积大；布尔并集只能按颜色分组，会破坏按 Branch 的交互和四种状态色，是一次大改 |
| `polygon-clipping` | 多边形布尔运算 | 比 paper.js 轻，接口直接 | 需要把每条锥形轮廓先展平成多边形，仍然不能跨不同颜色合并；本轮用父子覆盖已经解决接缝 |
| `bezier-js` | 贝塞尔求点、切线、分割 | 成熟 | 现有 `sampleAt` 只有二十行，且与弧长反馈绑定，换库没有收益 |
| `simplex-noise` | 连续噪声 | 能让曲率更自然 | 本轮形态由时间和数据决定，不需要再加一层随机场；引入后反而更难复现 |

结论：本轮不增加运行时依赖，包体积不变。分支连接用父枝覆盖子枝平口，叶茎从半宽处直接长出；如果以后要真正合并轮廓，再单独评估 `paper.js` 或 `polygon-clipping`，并先说明它会影响哪些交互。

## 参考的通用做法

- **变宽折线轮廓**：沿中心线按法线向两侧偏移，得到闭合轮廓；本轮沿用 `trunkOutline`，宽度按“之后还有多少调用”逐点变化。
- **逻辑时间到距离的单调映射**：`150 * log1p(age / 24000)`。它让短间隔不至于完全叠在一起，同时保证后到的事件只会追加，不会改变已画出的前缀。
- **确定性 hash**：同一个 Branch id 在任何一次渲染里得到同一个左右、角度、曲率和回摆，不读取浏览器时钟。
