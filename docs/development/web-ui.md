# control plane WebUI（2026-11-10）

2026-11-13 根部连接采用实际可见父边界位置映射与有限子侧过渡，直接构造两条三次曲线和闭合填充，保留 React Flow + SVG；连接与 bounds 共用控制点。子枝起点在父中心线，叶茎 placement 不变。用户已检查并接受当前画面，尚未穷举极端参数；公式与限制见 [连接状态](tree-connection-repair.md)、[投机树绘制参数](tree-parameters.md#固定分叉平滑连接2026-11-13)。

control plane WebUI 是 `--web` 模式下的正式浏览器界面。它只读取 control plane 已经发布的观察事实与按 Branch 的对话接口，不接触 Speculative Tree、控制命令或 Runtime 内部对象；输入仍走 `POST /api/request`。

Gateway 属于 control plane，与 UI 均不独立部署，由 control plane 统一启动和停止；这不规定必须同进程，也不要求自动打开浏览器。当前 HTTP listener、连接和 SSE 工作线程由 control plane 持有停止句柄并等待回收，细节及验证范围见 [Gateway 实现核查](gateway.md)。目标语义见 [control plane §2.1](../design/control-plane.md#21-gateway)。

## 技术组成

- React 19 + TypeScript，React Flow 绘制投机树，Zustand 保存观察状态。
- Vite 构建；源码位于仓库根目录 `webui/`。前端构建需要 Node 22.12 或更新的版本（当前验证使用 Node 26）。
- 构建产物位于 `webui/dist/`，不提交到仓库，由 `src/bin/ascout-control-plane.rs` 用 `include_bytes!` 嵌入 Rust 二进制，交给 Gateway HTTP 入口提供。根目录 `make` 统一构建前端和 Rust；直接运行 `cargo build` 不会启动前端工具链。
- `webui/dist/index.html`、`webui/dist/assets/app.js`、`webui/dist/assets/app.css` 与 `webui/dist/favicon.svg` 是嵌入入口；control plane 按固定路径提供它们。

### 生产构建

当前使用方式是在本机运行 control plane，用本机浏览器访问 loopback 地址。准备 Make、Rust 和上述 Node 环境后，在仓库根目录运行：

```sh
make
```

`make` 依次准备前端依赖、执行 `npm run build`（含 TypeScript 检查）、执行 `cargo build`；`make -j` 也遵守此顺序，任一步失败立即停止，前端失败不会继续 Rust 构建。首次使用、`node_modules` 缺失，或 `package.json`／`package-lock.json` 比 `node_modules/.install-stamp` 更新时执行 `npm ci`；成功后更新时间戳。每次 `make` 都重新构建前端，不提供前端增量构建保证。

`webui/dist/` 已列入根目录 `.gitignore`。直接运行 `cargo build` 时，缺少嵌入文件会在 `include_bytes!` 阶段编译失败；前端源码变化后未重新构建，则二进制仍提供旧界面。

## 界面行为

2026-11-16 展示范围与阶段目标：界面不做 Markdown 渲染，不显示图片；远程隔离环境只呈现文字事实与树状态，不提供远程文件浏览、终端画面或环境内操作。已接通 Agent 声明的 confirm/select/input/editor 文字提示、通知、命令清单与普通输入执行；工具批准由 Agent 扩展发问，界面原样回传答案，不解释拒绝后的行为。候选提示只在晋升权威后显示。语义见 [Agent 接入设计](../design/agent-integration.md) §3.1，实现与限制见 [接入实现](agent-access.md) §3.1。

2026-11-16 实现记录：`AgentPrompt.tsx` 提供是／否、选项、单行输入及多行编辑；明确取消时按 Pi 的取消值结束（确认 false，其余 undefined），无人回答则保持等待，不补默认答案或提示超时。`store.ts` 从状态事件集及现有 SSE 折叠未关闭提示、通知与启动命令清单，刷新／重连恢复当前已发布提示和缓存清单。输入 `/` 只筛选启动资源加载完成后取得的清单，不发 `get_commands`；换权威不清空清单。选中后通过普通 prompt action 发送命令原文；提示答案走独立回答入口，`/pause` 保持既有控制语义。断开时关闭提示控件。消息正文沿用 React 文本节点，未引入 HTML、Markdown 或图片渲染。`custom` 不支持；AScout TUI 也提供文字提示回答入口，操作见 [TUI 使用说明](reference-workload.md)。尚未做浏览器人工全链路验收。

左侧默认显示独立的“权威窗口”用户视图，跟随当前权威 Branch，展示从任务开始到当前的 `inherited`、消息与流式内容连续阅读流；它不显示 Branch 生命周期状态并允许输入。也可以切换到具体 Branch 窗口：继承自父 Branch 的消息与当前 Branch 的消息按先后顺序连续渲染，不折叠、不插入分隔线，当前权威 Branch 显示“当前权威窗口 · id”，历史权威 Branch 显示“id · 状态”，并在窗口标识中显示角色与状态徽标；历史 Branch 只读。发送后消息立即以“发送中”状态显示，服务器回显同一用户消息后移除临时条目，失败时显示错误。第一个版本从观察事件推导任务列表，control plane 没有单独的任务列表接口。

右侧是可隐藏的投机面板，默认显示投机树；点击顶部种子、工具叶片或模型叶茎进入该 Branch 的只读详情，可以返回树。树上不显示分支名，子枝不重复绘制枝头；悬停显示 Branch id、模型、token、Chance 字段、结算与调用/事件摘要。候选未采纳使用中性状态文字，不把用户视图描述为已清理。

### 投机树与统计

面板顶部汇总当前投机数量、累计 token、累计费用、累计节约时间和累计节约金钱。`settlement.time_ms` 与 `settlement.money` 的实测部分和估计部分分开累加、分开显示，不合并成一个数字；没有结算数据时显示“暂无数据”，不用其他数字填充。

树以 Branch 树自身为几何依据，枝长和粗细都是观察事实的函数。布局前先配对：每次工具调用归到它之前最近的那次模型调用，形成“模型调用 + 它发出的工具调用”的单元；找不到所属模型的工具调用属于数据缺陷。所有调用必须带 `started_at_ms`：缺失时整棵树显示错误，不跳过、不用事件序号补时间。纵向位置逐截计算：第一次调用位于 0，之后每两次相邻调用开始时间之间是一截，默认长度为 `60 × ln(1 + 间隔/10000ms)`，位置逐截累加；间隔相同的两截长度相同。Chance 不切分截长，只在相邻两截之间按源侧准入请求时间线性插值。枝长最多到最后一次调用；当对应子枝已被接受时进一步按该 Proposal 的真实验证完成时间截止，丢弃或清理等生命周期事件不延长枝长。多个调用时间相同时，它们共用同一纵向位置，不产生零长采样段；只有一个位置时仍按该处枝宽绘制横截面。

枝的粗细按该位置扣除工作量后的剩余调用占比计算，条目间用 smoothstep 过渡；默认宽度指数为 0.1、最小枝宽 1.2。根宽是独立树内参数（默认 9 单位），不随时间映射变化。子枝根宽为父枝分叉处宽度乘以该子枝调用数在相关剩余调用中的占比的 0.1 次方；指数可调，详见参数文档。普通枝末端平口结束，单位置父枝的非空子枝使用圆根。

子枝从 Chance 的源侧准入请求时间对应的父枝中心线位置分出；这是已确认的投机起点口径，不代表已被 `select` 选中或候选已启动。偏向侧别由分叉点相对本枝起点轴的横向偏移和稳定哈希决定，向右概率为 `clamp(0.5 - (local.x - nodeOrigin)/(2R), 0, 1)`；初始相对夹角在默认 30–90° 范围内用 `${id}/childAngle` 稳定采样，偏向侧初始绝对方向超 90° 时选另一侧。实际首段参与逐截方向插值。只有一个候选时，其在父枝局部法线上的投影决定父外沿上的 Chance 侧别。子枝中心线起点保持在父中心线上。

枝的弯曲是逐截随机行走：每截有一个相对于上一截的方向角。横向位置以本枝起点轴为零点，向右为正；默认向右概率 `p = clamp(0.5 − (x + 60 × sin θ) / 120, 0, 1)`，用该截末次调用标识的稳定哈希决定左右，每截转 18°，下一截方向角限制在 ±72°；初始方向按子枝选侧规则确定。每一截只依赖它之前已经画出的位置与方向，因此追加更晚的调用不会改变已画出的前缀。

一个 Branch 是一根大枝。每次模型调用是一根短叶茎：完成时间映射到枝的中心线位置，以当地切线和宽度生成同枝色无描边的填充轮廓。长度为 `10 × ln(1 + 模型秒数)` 树内单位，没有屏幕像素上下限；宽度取最大宽度与局部枝宽比例上限的较小值。叶茎与本枝最终可见轮廓进行两侧平滑连接；无有效连接时保留普通闭合轮廓，端部画半径为半宽的端帽。单位置枝仍显示其实际截面。叶茎按完成距离依次对附近同侧子枝和已放叶茎比较角度间隔，侧别同分保留稳定反侧偏好；固定倾角保持固定值。模型调用发出的工具调用是叶茎上的叶片，沿茎排开，叶长随工具耗时在 10–24 树内单位之间变化；叶片画成椭圆，没有尖端；中脉为本色偏暗的细线。叶片只按角度散开，不做面积避让。参数与精确规则见 [树形参数](tree-parameters.md)。

状态只改样式，不移动任何枝干。当前权威是近白（浅色主题近黑）实色；曾经是权威的枝，包括已经结束、已经让位给当前权威的旧主干，保持同色，但按 72% 与背景混合成较淡的实色，不使用透明度，避免透出下层子枝的颜色；从种子到当前权威仍然是一条白线，只在旧权威段略微变淡。运行中的候选为粉紫；未采纳或未晋级就被清理的枝为灰色、整枝 40% 透明、叶片统一变枯。调用状态是另一个通道：成功为实心绿，失败为实心红，取消为空心灰，超时为空心琥珀；候选枝上的成功叶改用该枝的玫红（`--leaf-candidate`），避免粉枝绿叶的割裂，失败/取消/超时仍用各自的颜色。枝的透明度包住叶片，所以未采纳枝上的叶子不会保持鲜绿。均不用虚线。叶茎只有一种颜色来源：所属 Branch 的显示状态。不会再出现“叶子在树上分叉点以下就变粉、但所在 Branch 仍是白干”的两套规则。

视觉审阅用手工事件对照同尺寸画布。离线 Chromium 验证长无叶模型茎的末端由画布外进入画布，拖动后追加 Branch 保持屏幕变换。多候选圆点悬停列出两个候选，点击不进入详情，两个候选可分别从叶茎进入。单候选圆点的几何与点击行为保持一致。

每个 Branch 是一个 React Flow 节点；非空枝有连接时使用连接闭合轮廓，null 时使用普通枝干。Chance、叶茎、叶片与芽在同一随 React Flow 变换的 SVG 组中。只有一个候选时，Chance 圆心在父外沿，默认半径为子枝实际根宽的 0.05 倍，点击圆点进入该候选。零个或多个候选时，Chance 仍只有一个圆点，其圆心和半径基准取自父枝在 Chance 处的采样位置和宽度。多候选圆点悬停列出各候选，点击各自的枝或叶茎可进入详情。真实缩放同时缩放圆点和全部墨迹。空 Branch 的芽为沿初始方向放置的实心椭圆，不生成连接。

曲线按固定空间间隔采样，成本随可见长度线性增长，不通过反解对数遍历逻辑时钟。方向由逐截行走决定，追加事件不会改变已有前缀。树初次显示时按已有的完整几何边界取景，边界涵盖无工具叶片的模型叶茎，目标上下各留 50px、左右各留 44px，初次缩放最大 1 倍。画布保持打开时，新增 Branch 和调参均保留当前视野。「最新」按事件序号比较已绘制 Branch 与可定位的 Chance。若最新的是 Chance，则定位到它已绘制的父枝。手动缩放上限为 4 倍。模型叶茎与工具叶片可分别用点击、Enter 或 Space 打开各自的调用详情。暗色权威色为 #F4F8FC，浅色近黑，候选为粉紫，未采纳为灰并整体淡化，枯叶为 #9C8A6E（浅色 #8A7A5C），与图例一致。

调用密集时相邻叶簇可能重叠，当前不做面积避让。连接覆盖、额外材料与 null 图标记存在严格验收缺口，见连接状态文档；几何辅助量与截图证据分开报告，不以脚本运行完成声称整轮通过。

### 性能目标与实现差距（2026-11-14）

已定目标：树隐藏或进入 Branch 详情后，几何仍随几何输入变化继续更新，可见性不是暂停计算的条件。对话内容与几何输入分离，无关对话或纯展示变化不触发几何重算；未变化的几何复用，返回树直接使用最新有效结果。速度、CPU 与内存均需兼顾，辅助展示不能挤占核心系统资源；缓存有界，及时释放不再需要的结果。以上不改变现有绘制语义。

2026-11-14 实现：观察 store 保存当前选中 task 的最新 `treeGraph` 和调参；事件接收、状态重同步、任务切换及调参时更新，不依赖树组件是否挂载。返回树只消费最新 graph。缓存只保留当前 task 各 Branch 的最新一份结果及中心线采样，不保留历史版本；任务切换、空 task、stop 或布局错误释放缓存，移除 Branch 后替换缓存表。缓存大小随当前树规模增长，不是固定字节上限，也不限制观察历史本身。

几何签名不包含对话正文、生命周期状态、token、费用、模型名称或工具状态。当前节点、调用组和 tooltip 仍使用最新的观察事实。布局命中时复用路径、轮廓、连接和 bounds。调用事件引用未变时复用整份几何。几何签名包含调用身份/类型/开始/完成/耗时、Chance 归属与源侧准入时间、已接受 Proposal 的验证截止时间、父连接输入、全树结构与各枝后代调用总量及全部调参。父几何变化向后代失效，直接子枝时间及 Chance 时间也进入父签名，避免父 Chance 外沿/子根宽依赖遗漏。结构、调用数量和调参采取保守失效，不假定新增调用只影响末端。

第二层缓存独立复用中心线采样：只依赖初始方向、调用开始时间及顺序、时间映射、回中、转向、倾角和采样间隔。因此宽度、耗时或连接参数改变时，即使最终几何必须重建，未变化的采样仍可复用。暂未做单枝追加时的采样前缀、逐叶茎连接或局部宽度轮廓复用；父级重建也可能使实际未变的后代最终几何保守重建。树输入未变时，store 直接返回已有图。UI 事件、其他任务的事件、只改运行状态的事件和等值调参均走这条路径。树输入变化时，按父枝索引子枝及 Chance，复用数据、几何和层级未变的节点。狭窄范围内的修改仍可能触发全树几何检查，长运行帧率、总 CPU 和堆内存收益有待验证。

验证：`tests/tree-layout-cache.mjs` 先在缺少缓存 API 时失败，修复后 4 项通过；与现有布局和地图历史测试联合共 20 项通过（原独立的 stem placement 六项现合并在 `tests/tree-layout.mjs`，共用 Vite loader）。缓存与全量布局逐字段比较覆盖父宽/子枝、Chance 时间、调用时间、结构修改及所有调参字段；纯展示变更的 Branch tone 与调用详情文案也核对新事实。三枝样例初始计算 3 枝，纯展示后仍为 3；连续两次子枝耗时更新累计为 5（每次仅 1 枝），中心线计算始终为 3。详情及隐藏期间两次新增调用使累计为 9，无关对话后仍为 9；隐藏期间调参后为 12，返回仍为 12。100 次版本更新后缓存仍只有当前 3 个条目，错误/stop 后为 0。计数证明跳过对应计算，不代表生产负载耗时比例。

### 源侧起点与父枝截止（2026-11-14）

`chance_created.speculation_started_at_ms` 来自 Instrumentation 本地 `admit` 通过后发送准入请求时的 `Date.now()`；无候选的 Chance 也从该字段定位。它是约定的投机起点，不是候选启动的证明。记录追加时刻只表示 Ledger 写入时刻，不用于定位。

control plane 在对应 Proposal 的 `match` 求值完成后、`dispose` 之前记录验证时间；公共 `proposal_validated` 绑定 Chance、Proposal 与该次验证工作 id。只有 Agent 确认 Promote 后的 `accepted` 引用用于那次 Promote 的 id；重复验证、等待祖先和 Promote 失败不会将较早或其他 Proposal 的验证冒充最终依据。接受前保留完整父枝；接受后父枝沿原调用时间映射最多画到验证时间，不延长到最后调用之后，端点显示短横线及悬停说明。验证点之后开始的父枝调用不在树上绘制，仍属于原父枝并保留在详情中；之前开始但完成较晚的模型调用保留，叶茎锚点限制在截止范围。

源时间或已接受 Proposal 对应验证时间缺失、不匹配时显示明确绘制错误，并清除缓存，不用记录、Promote 或旧的成功结果替代。旧记录中未携带这些字段时同样如此。无候选机会、时间修正、隐藏和详情期间接收验证、缓存与全量结果一致及错误清除已用手工事件检查；真实模型和浏览器画面尚未验收。

本轮检查：`cargo check --all-targets`、`cargo test --lib`（提交前复跑 163 项）、树布局/缓存/叶茎/地图 Node 检查（21 项）通过；先构造准入与 Ledger 时间不同的事件使定位断言失败，再接通并通过。`npm run build` 当时曾被工作区既有 `ChatPane.tsx` 的 `pause` 不属于 `Request` 类型阻断；提交前复核时该阻塞已不存在，`npm run build`（含 `tsc -b`）与根目录 `make` 均通过。`tests/pi-access.mjs` 的 6 项因当前工作区 Pi 接入要求加载 `packages/coding-agent/src/core/tools/index.ts`，而伪 Pi fixture 未提供该模块，均在等待消息时失败；没有把这组测试称为通过，也未修改该独立的文件工具工作。

## 当前缺口

绘制参数及公式见 [投机树绘制参数](tree-parameters.md)。参数集中于 `tree/tuning.ts`，支持数值输入、滑杆、固定/范围随机；临时调参面板自身的宽度调整见该文档，整个投机面板调宽见上文。

空 Branch 由自己的节点画出实心椭圆芽，可点击该芽进入候选详情。

- 枝段长度按相邻调用开始时间差逐截计算；缺少 `started_at_ms` 时整棵树报错。Chance 按 Instrumentation 准入时间在相邻两截之间插值并限制在枝端范围内；缺少源时间时不猜测。
- 树的横向位置由逐截随机行走与回中概率决定；还没有按整棵树的墨迹质量做配平，长枝多的一侧可能更宽。
- 历史聊天浏览的需求是像普通 chatbot 一样，通过列表回看以前聊天（2026-11-16 确认），不是事件级回放。当前没有任务列表接口；任务从事件中的 `task_id` 推导，首个事件到达后才会出现，任务切换状态保留在客户端；这些实现事实不等于已支持上述历史聊天浏览。
- NLE 地图浏览位于独立的 `/map` 入口；它读取同一 task 的真实 Runtime `nle_map_action` 公开观察事件，作为跨 Promote 的权威窗口历史；Branch 只显示为动作来源，不按单 Branch 筛选。没有事件时才使用明确标注的演示序列；不同 task、乱序或无效事件仍不会被伪造为同一条完整时间线，详见 `docs/development/nle-map.md`。
- 对话正文仍按需读取；权威窗口按 `authorityHistory` 依次读取并连续展示已成为权威路径的内容，按 Branch 查看仍是独立窗口。消息组件使用稳定身份和 memo，观察事件只使末尾数据刷新，滚动仅在用户仍贴近底部时跟随；Ledger 的 transcript 保存权威 session 文件的消息引用，正文存于该文件，继承由记录父链表达；这些内部引用没有进入公共观察事件，不能把文件中的全部候选旁支当作已生效对话。
- 模型投机当前没有生产路径；面板按事件结构显示，不假设模型投机一定发生。
- `tool_finished.tool_name` 只在 Instrumentation 报告过同一 action 的 `ActionStarted` 时存在；只有准入请求时该字段为 null，界面显示“未上报”。
- 统计只累加已上报事实。`model_usage` 缺 token 或费用时不补零；结算的实测/估计部分缺失时对应项显示“暂无”。

### 最值得讨论的四组问题（建议均未确认）

1. **长度/回中参数还决定离散选侧，是否需要独立调试？** `stemK/stemTauMs` 同时改变 S 和 P:17 的邻居判定 `|d邻−d茎|≤S`。例如模型耗时 1000ms、τs=1000 时 Ks=10 得 S≈6.93，Ks=20 得 S≈13.86；距 10 的同侧邻居由不参与变为参与，可能整根叶茎换侧。`recenterRange` 同时进入 G:289 的本枝转向和 G:379 的子枝偏侧，后者又影响叶茎 placement。**建议**：优先确认是否保留这两种共用；若需要“只拉长不换侧”的测试，再讨论将避让范围与 S 分开。转角、局部切线及附着点随父几何改变的自然依赖不列为应解除项。K 与 τ 是不同自由度，不能因小间隔下 `L≈(K/τ)Δt` 就直接合并。

2. **连接参数共用于两种对象，且一个值同时影响端点和控制柄。** G:464、486 同时传相同两比例，分别乘子枝根宽或茎宽 W。C:54–67：父展开 `min(2W,W/(2a)+rp W)`；子终点推进 `min(D/a+rc W,子侧位置长/2)`；控制柄包含 `max(W/6,2rW/3)` 并受弦长限制。若 a=1，rp 从 .15 调至 .25，父展开从 .65W 到 .75W，但控制柄内部下限仍为 W/6；rp> .25 才可能抬高这一内层量。a=.25 时父展开从一开始就截为 2W；短子侧也很容易触及半长上限。两个比例均为零仍有基础连接，不等于关闭平滑。**建议**：先确认子枝/叶茎是否需要分别调；端点与切向柄的几何关系优先保留，并解释夹限，不因局部不敏感就删参。是否分离端点距离与柄长需另获确认。

3. **上翘有精确乘积冗余；叶长的多个参数则并非同一种冗余。** G:214–215 只消费 Bcy、Bey：固定 B=1、cy=.1、ey=.14 与 B=2、cy=.05、ey=.07 给出相同曲线（其他输入相同）；固定模式三个数只提供两个有效上翘组合。若 cy=ey=0，B 的固定值/随机范围都无效。相比之下叶长四参数分别控制下限、上限、饱和时长与曲线，只有 `leafMin=leafMax` 或所有样本均饱和时才失去部分作用。例如默认 t=T=12000ms 时叶长必为 24，与 τl 无关。**建议**：固定上翘模式考虑只保留两个有效控制或将 B 作为便捷总倍率（不把三者都当独立形态自由度）；随机 B 统一改变两项的相关性有意义，不能直接当重复删除。叶长参数先按实际样本是否能区分效果判断，而非一律合并。

4. **粗细参数跨对象传递并有双重用途，如何区分语义与可见性？** W:7–8 的剩余占比指数和 G:496–499 的子枝占比指数共用 e，代表两处有意的调用量编码，是否分开不能仅按外观决定。m 同时决定最细枝与单位置截面描边（G:429）；例如合法 m=20、根 W=9 会使该根枝宽全部为 20，隐藏剩余调用差别。叶茎当地枝宽为 1.2、比例 .9 时 w=1.08，将 stemWidth 从 2.2 增到 4 不改变实际宽度；当地枝宽为 9 时上限 2.2 起作用，增加比例也不改变宽度。默认无叶末端圆 r=1.5，而端帽半径可达 w/2，当 w≥3 时圆可被同色端帽遮住。**建议**：保留并解释调用量编码；优先确认 m 的截面描边用途是否需要分开，以及叶茎宽度是否仍需同时保留绝对/相对两个上限。Chance、提前量和连接按宽度同比例变化属于明确外观关系，不自动拆开。

当前只提出上述四组待讨论问题，完整参数表是审计证据，不作为大量新待办写入根 `Discussion.md`。本节新增了对既有文档“Chance 半径为根宽一半”的事实校正：当前代码是 `chanceRadiusRatio`，默认 .05；未改默认值。
