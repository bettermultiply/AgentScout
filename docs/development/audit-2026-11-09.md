## Firecracker 错误链补充（基线 0185ede）

- 红灯：新增停止失败回归在原实现报告 `process handle lost after stop failure`；
  目录失败回归报告网络分配已丢失；网络命令注入拒绝后 cleanup 却返回 Ok。
- 修复后停止失败保留 Child/原状态，不拆资源；网络或目录失败保留环境/分配。
  重试成功才移除环境并释放分配。启动配置和准备失败使用相同的停止→网络清理
  顺序，失败回滚保留环境并附加 cleanup failure，外层不再删其目录。
- 网络删除只接受精确的缺失资源诊断，固定命令 locale；权限、sudo 和执行错误
  返回调用方。部分删除后的重试允许资源已不存在。setup 的残留删除也不再吞错误。
- SIGKILL 和轮询错误明确报告，等待退出五秒超时返回，不再无期限 wait。
   生命周期通过每 id 操作锁串行创建、移除、重用、暂停、恢复及终止；不同 id
   不持有同一个长锁。branch 按 id 字典序取得父子操作锁，拒绝同 id，之后才取
   父环境锁，避免反向 branch 的取锁循环。注册表锁只用于短时查找/更新；没有
   持注册表锁等待环境锁的路径。环境锁覆盖快照窗口和生命周期状态更新；operate
   只在短锁中检查 Available 并复制 socket，guest_command 全程不持环境/操作锁，
   允许 terminate 在长命令期间停止 VM。已发出的 guest 命令可能随 VM 停止失败。
- 无特权测试使用 thread-local 故障注入与普通 sleep 子进程，没有执行真实
  sudo/mount/iptables/Firecracker。Firecracker E2E 仍未运行。
- 最终验证：`cargo test --lib --bins -- --test-threads=1` 为 119 个库测试和
  1 个 bin 测试通过；`cargo build --examples`、`cargo test --no-run` 和
