# Filesystem Backend 目标

## 目标

为投机执行提供文件系统隔离。

- 分支之间的写入必须相互隔离，且后代分支的写入不得影响祖先分支。
- 分支被接受后，必须形成正确的合并文件视图；分支被丢弃后，必须能够低成本移除其文件视图。

## 进阶目标

- 允许只接受或合并分支写入产物的一部分，而不是只能整体接受。
- 祖先分支的后续写入对后代分支可见。
- 尽量降低写入延迟、写入吞吐损失、CPU 消耗、启动成本和系统调用额外开销。

## 约束

- 文件系统隔离不能依赖特定 Agent 和底层文件系统实现，但这不意味着不能使用类似 OverlayFS 的方式。

## 设计构想

- 隔离重点是实际产生存储写入的路径，尤其是 workspace 和常用的 `/tmp` 等 tmpfs。
- 第一版计划先采用创建时固定的 Parent 状态。
- 第一版可以在合并后直接以类似 Git merge 的方式显示冲突。
- syscall 拦截、eBPF、使用 SQLite 等方式代替普通文件系统写入，属于后续可评估的实现方向，不属于当前讨论层次。

## 澄清

- 虚拟机、容器等隔离方式不会影响文件系统隔离，因为文件系统隔离可以嵌套在其中，同样服务于 Agent 进程。
