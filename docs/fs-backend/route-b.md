# 路线 B：FUSE 与自有文件状态存储

## 核心思路

使用 FUSE 在用户空间实现文件系统视图。FUSE 根据路径和操作决定从 Parent 状态读取，或将 Branch 的写入保存到独立存储。独立存储可以是普通目录、内容寻址存储、数据库或其他由 Backend 管理的形式。

```text
Agent 进程树
    ↓ 访问
FUSE 文件系统
    ├── 读取 Parent 状态
    └── 保存 Branch 独立写入
```

## 能力来源

- FUSE 提供用户空间文件系统接口。
- 自有存储负责保存 Branch 的文件内容和目录状态。
- Filesystem Backend 负责 Branch 的创建、生命周期、接受、丢弃、差异和合并。
- FUSE 层可以在处理写入时直接记录文件变化。

## 优势

- 不要求底层文件系统提供快照或写时复制能力。
- 可以直接定义 Branch 文件视图和写入保存规则。
- 可以自然记录新增、修改、删除和重命名等文件变化。
- 可以从设计初期支持基线、差异、冲突和部分合并。
- 数据库或其他自有存储可以作为 Branch 状态的后端。

## 不足

- 需要自行实现和验证大量文件系统语义。
- 文件操作经过用户空间，可能增加写入延迟、CPU 消耗和系统调用开销。
- `rename`、`mmap`、文件锁、硬链接、符号链接、权限和异常退出等行为需要专门处理。
- FUSE 服务退出、挂载清理和进程树生命周期需要额外管理。
- 与任意 Agent 和现有工具的兼容性需要大量验证。

## 第一版定位

路线 B 不作为第一版首选。它适合作为未来需要更强文件变化记录、差异和合并能力时的实现方向，也可以作为路线 A 无法覆盖特定底层环境时的候选实现。
