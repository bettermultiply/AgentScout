# 问题与目标

本文是 [心智模型](mental-model.md) 定位部分"现在存在什么问题"与"AScout 能做到什么"的展开：先论证为什么需要投机执行、现有工作缺什么，再给出 AScout 的目标。

## 1. 投机执行

当前 AI Agent 的智能到达了一个前所未有的高度，强大模型之间的差异已经越来越难以通过简单的方式区分。在 Agent 的使用体验上，对智能的优化得到的回报会越来越小。与此同时，单次调用模型的成本也在逐步下降，很多模型通过极其低廉的价格提供了强大的智能。但现有的 Agent 交互仍然面临大量的等待时间，用户需要花费大量时间等待 LLM 推理、Agent 的工具执行完成，对用户体验造成较为严重的影响。因此对 Agent 使用体验的追求会逐步从对智能的追求转向对交互速度的追求。

更具体而言，Agent 在执行过程中经常需要等待一个慢结果，包括模型推理、用户输入决策、测试执行、远程 API 调用等等。后续的执行推理通常依赖于这个慢结果才能继续，在等待过程中整个执行流程都被阻塞，严重影响 Agent 运行速度，甚至主导整个流程。另外，现有的研究表明，在 coding Agent 执行过程中，模型推理和工具执行的时间各占 Agent 运行的大约一半时间。这意味着无论是单一的优化工具执行速度，还是优化模型推理速度都只能得到有限的加成。

投机执行就是一种加速整个运行过程的手段。它在慢结果未到时，通过“预测”的方式提前为后续步骤提供输入，提前启动后续步骤的执行。在后续节点，如真实的慢结果到达后，通过比对验证的方式，决定对提前启动步骤的处理。当接收提前启动步骤，则有效地加速了整个过程。若未接收，也几乎不会对原始运行流程造成影响。

从上述描述中可以看出，想要实现有效的投机执行主要问题有两方面。
1. 如何规划整个投机执行的运行，包括决定投机执行的位置、如何预测慢结果、如何进行比对、如何处理提前步骤等等。
2. 如何保证提前启动的步骤和原始流程不会相互影响。

## 2. 现有问题

现在已经有不少的工作开始研究 Agent 的投机执行了。也都是围绕着上述的两个方面展开。但他们都存在一定的问题，具体来说包含策略孤岛、隔离碎片化、和上下层脱节三个方面。

### 2.1 抽象策略分散

现有的投机执行工作通常围绕特定任务、执行对象、执行步骤进行设计。与此同时，预测、执行、验证、复用和失败处理被封装在不同的算法中，独立存在。这导致不同策略之间缺少统一的抽象和语义接口，难以组合，也难以根据任务的状态、资源条件和风险水平绑定不同策略。

### 2.2 状态与副作用处理碎片化

不同工作对投机执行的隔离对象、隔离范围和安全强度采用了不同假设，有的只允许 read-only、幂等或可逆操作，有的则直接禁止高风险操作，有的只缓存 future 或结果，有的隔离 filesystem 或 GUI。对于 network、database、email、payment 等外部副作用，通常采取禁止、延迟、特定环境或补偿执行。

这些机制缺少统一的语义表达，无法回答一个投机执行过程能够在哪些状态域中暂时生效？其结果对谁可见？验证失败后应当丢弃、重执行还是补偿？现有工作通常只能在具体任务或具体系统中回答这些问题。尚未形成一个被普遍采用的、能够跨任务和跨状态域描述投机执行及其副作用处置的统一框架。

### 2.3 策略与运行时缺少协调

现有工作分别在投机策略和执行隔离两个方向形成了丰富的局部机制，但二者之间尚缺少统一的跨层契约。投机算法通常通过限制操作类型或依赖特定环境来间接表达其对隔离、可见性、验证和失败处理的需求，与单一算法强耦合；底层隔离系统则通常不理解投机执行的通用语义，如预测的置信度、执行步骤的语义、候选结果的等价性以及不同失败处置的代价。

因此，现有系统难以让不同投机策略以统一方式声明执行需求，也难以让同一套底层隔离、验证和副作用处置能力被不同策略组合复用。

## 3. 目标

AScout 旨在构建一个位于投机策略与执行机制之间的通用中间层，它通过统一的投机执行机制承接不同 Policy 与 Runtime 构成一个投机执行的通用底座。使投机策略能够独立于具体运行时实现进行设计和组合，Runtime 也能够提供投机执行所需的基本能力，而不与某个特定投机算法耦合，来解决上述的问题。

Policy 在 AScout 所定义的语义范围内表达和组合具体的投机执行策略。Runtime 通过 Adapter 接入 AScout，并提供投机执行所需的基本能力。AScout 负责承接两者之间的差异，协调策略决策与运行机制之间的衔接，并保证投机执行遵守既定的正确性、隔离、资源和副作用约束。具体策略能否执行，取决于所选 Runtime 的能力与相应契约；能力不足时，AScout 应拒绝执行或进行明确降级，而不能静默改变策略语义。

在使用过程中，Agent 可以通过 AScout 提供的接入方式获得投机执行能力，而不必修改自身的执行逻辑；用户默认无需感知背后的投机分支。是否实际进行投机、能否复用提前执行的结果以及是否产生性能收益，则由 Policy、Runtime 能力和具体运行条件共同决定。
